# Generation context and repair

## Input and evidence

Generation receives one component's declarations, complete source type graphs, owner implementation, saved exploration judgments and target context. Repeated candidate observations and global source diagnostics are summarized inline. Full original context, dependencies and exact compiler observations remain in immutable private invocation artifacts. The summary explicitly retains coverage uncertainty; absent inline observations never prove that an input is unused.

Native and model decision skeletons come from the canonical source graph and existing definition serializer. They provide exact source identities, candidate IDs and structural metadata. They do not select a category, authorability, null equivalence or representation; those judgments remain with the agent and canonical host validation.

## Exact-output preflight

The supplied validator receives the exact tool-call lines intended for final output. It uses immutable evidence and the attempt's accepted-decision snapshot, preserves accepted semantics and validates source-bound representation admission. Only a successful complete draft records a receipt, identified by a digest of normalized tool decisions. The host checks that the emitted decisions have that receipt and independently repeats admission checks. Prose, JSON whitespace and ordering of distinct subjects do not change decision identity; changing a decision does. Failure to prepare the validator stops generation before spending agent attempts.

The validator can run repeatedly within one agent invocation. It writes only the invocation's receipt file, without changing source, evidence or repository state. Missing tool access or incomplete validation cannot be reported as successful completion. All artifacts remain available until subprocesses settle and are then disposed.

## Repairs and repeated errors

Five attempts share one operation deadline. Valid decisions are retained; corrections receive only failed subjects, relevant property facts, their candidate skeletons, pending semantic decisions and summaries of successful choices. Original source and task context remain available for targeted artifact inspection. The correction validator includes accepted decisions automatically, so agents do not need to replay them.

The first correction addresses exact errors. Repeated equivalent failures change the strategy to evidence investigation, followed by reconsideration of supplied compatible alternatives. Semantic locks, source domains, requiredness and source identities remain protected. Repetition never authorizes invented types, domain narrowing or exclusions used to bypass representation failure.

## Measurement and verification

Saved decision debug records include attempt strategy, repeated-failure count, prompt and response character counts, full-context size, elapsed time, diagnostics and exact-output receipt status. Debug events expose the same measurements without embedding prompt or source content. These measurements support comparisons of first-attempt success and total generation time on subsequent runs.

Verification for this change uses package builds, typechecks and lint plus measurements of saved prompt artifacts. No new live agent evaluation or persistent cache behavior is introduced.

A saved seven-property component had a 1,116,990-character generation prompt. Rebuilding its task context with the new scope produced 94,810 characters before the host inventory and representation identities; its identity/skeleton block added 17,727 characters. Repair task instructions were 48,835 characters before focused failed-subject evidence. This measures input reduction, rather than agent latency or first-attempt success; those outcomes require subsequent runs.
